# 复杂度与边界静态审计清单（XCPC 十大死法）

用于在**不运行代码**的情况下快速定位嫌疑点。审计顺序建议按"命中率"降序：
先看多测与边界，再看溢出，最后看复杂度。

## 审计清单

### 1. 32 位整数溢出

- `int sum`、`int ans` 累加 `n * 1e9` 级别数据；
- `mid * k`、`a * b` 未转 `long long`（应写 `1LL * a * b`）；
- `1 << 31`、`1 << k (k>=31)` 未用 `1LL << k`；
- 距离类 `INF` 取 `0x3f3f3f3f` 但边权累加超过 `int`；
- `#define int long long` 后忘记 `signed main()`。

**检查方法**：把所有可能出现 `N * max(A_i)` 的表达式列出来，问一句"最坏情况能否超过 `2^31-1`"。

### 2. 多测未清空 / 清空不彻底

- 只 `for (i=1;i<=n;i++)` 清空，却访问了 `n+1`（差分数组经典坑）；
- 清空了 `vis[]` 却没清 `head[]/nxt[]/ecnt`（邻接表）；
- 清空了数组却漏了 `cnt`、`sum`、`mx`、`flag` 这类标量；
- `memset(a, 0, sizeof a)` 在大数组 + 多测下 TLE（应只清 `1..n`）；
- `vector` 复用没 `clear()`。

**检查方法**：搜索所有全局变量，逐个回答"第二组数据进来时它还是上一组的值吗"。

### 3. 极小边界

- `N=1`：`for (i=1;i<n;i++)` 一次都不执行，答案是否仍正确；
- `K=0` / 空集 / 空区间：是否读到非法下标；
- 全相同元素、全 0、全负数；
- 树退化为链、图退化为单点；
- 取模题为 `1`、`MOD-1` 的幂。

### 4. 数组开小

- 树题 `N` 个点却只开了 `N` 而不是 `N+1`；
- 边数 `2*(N-1)` 只开了 `N`；
- 线段树开 `4n`，但动态开点是 `log` 倍；
- 字符串题 `char s[N]` 忘记结尾 `\0`。

### 5. 越界与 UB

- 循环 `for (i=0;i<=n;i++)` 访问 `a[n]`（下标应为 `0..n-1`）；
- 负数取模 `(a % MOD + MOD) % MOD` 缺失；
- `swap(a[i], a[i])`、自环、重边；
- 迭代器失效（`erase` 后继续用）；
- 有符号溢出（UB，`-O2` 下会被优化出反直觉结果）。

### 6. 递归爆栈

- 链状树 `N=2e5` 用递归 DFS（Windows 默认栈 ~1MB，必炸）；
- 递归 `solve(l, r)` 深度 `O(N)`；
- 改迭代 or `sys.setrecursionlimit`（Python）/ 手写栈。

### 7. 未关同步流 / 输出过慢

- 大数据题缺 `ios::sync_with_stdio(false); cin.tie(nullptr);`；
- 全程 `endl`（每次 flush）-> TLE；
- `cout` 输出 `1e6` 行未用缓冲。

### 8. 复杂度常数

- `O(N log N)` 但 `log` 带巨大常数（`map`/`set` 嵌套）在 `2e5` 下 TLE；
- 多测每题 `memset` 整个 `1e5` 数组 -> `T * N` 爆炸；
- `unordered_map` 被卡哈希（应用自定义 hash 或换 `map`）。

### 9. 精度与浮点

- 直接 `if (a == b)` 比较 `double`；
- 二分 `while (r - l > 1e-6)` 但需要 `1e-9`；
- 累加误差导致排序比较不满足严格弱序（`sort` 会 RE）。

### 10. 输入输出格式

- 多测少输出换行 / 多输出空格（PE）；
- `%d` 读 `long long`（应 `%lld`）；
- 读入字符时残留换行（`cin >> c` 前有 `getline`）；
- 输出 `-0`、`-0.000000`；
- 多解题只输出了一种方案就以为错（其实需要 SPJ 才能判）。

## 审计输出格式

按「根因 -> 证据（行号）-> 触发条件 -> 修复建议」四段输出，证据必须来自 `read` 的真实行号：

```
[根因] 多测未清空 diff[n+1]
[证据] wa.cpp:23 `for (int i = 1; i <= n; i++) diff[i] = 0;`，而 wa.cpp:41 处理区间时访问了 diff[r+1]，r 可取 n
[触发] T>=2，且前一组存在 r=n 的操作、后一组 n 更大
[修复] 循环上界改为 n+1（或每组 memset 前 n+2 个元素）
```

## 使用建议

1. 先跑 `run_stress_test` 拿反例（动态证据最强），再用本清单解释根因；
2. 若无反例但怀疑 TLE/RE，按第 1/6/7/8 条做静态推断，并让 Subagent 构造 `N=2e5` 链或极值数据实测；
3. 审计结论要落到**具体行号 + 具体触发数据**，否则等于没查。
